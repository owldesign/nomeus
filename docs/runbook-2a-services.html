!Troubleshooting

postgres: "postmaster became multithreaded during startup … Set the LC_ALL environment variable" — the agent's environment had no locale; macOS's setlocale fallback spawns a thread and Postgres bails. devkit's agents now carry LC_ALL/LANG. An instance created before that fix is a crash loop: devkit services:delete <name> --force and recreate.
"did not start answering on 127.0.0.1:PORT after 30s" — the agent loaded but the process died. The last log lines are in the message; devkit services:logs <name> for more. Postgres: usually data-dir permissions or a stale postmaster.pid; MySQL: logs/mysql-error.log.
launchctl bootstrap: "Input/output error" (5) — the plist is malformed or an agent with that label is already loaded under a different plist. plutil -lint ~/Library/LaunchAgents/dev.zhuk.devkit.svc.<name>.plist and launchctl print gui/$(id -u)/dev.zhuk.devkit.svc.<name>.
launchctl enable/disable: "Domain does not support specified action" (125) — the command ran outside your login session (SSH, or a task context that can't see gui/UID). Run the same devkit services:… from a local terminal; if it only ever fails from the dashboard, that's the 2b fallback.
initdb: "could not change permissions of directory" — the data dir isn't owned by you. ls -ld ~/.devkit/services/<name>/data; devkit creates it as you, so this means the directory pre-existed.
Formula installed but "has no bin dir" — keg-only or a formula that puts binaries elsewhere. ls $(brew --prefix)/opt/<formula>. Not the case for postgresql@*, mysql@*, redis.
