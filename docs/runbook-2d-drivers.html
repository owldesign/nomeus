1Meilisearch ~3 min

devkit services:create meilisearch && curl -s http://127.0.0.1:7700/health && echo && devkit services:env meilisearch
brew install meilisearch (first time) · starting meilisearch on 127.0.0.1:7700 · {"status":"available"}
SCOUT_DRIVER=meilisearch · MEILISEARCH_HOST=http://127.0.0.1:7700 · MEILISEARCH_KEY=
Development mode, no master key — Scout's meilisearch driver works with an empty key. A site's .env gets these three lines and composer require laravel/scout meilisearch/meilisearch-php.

2Typesense ~4 min

devkit services:create typesense && KEY=$(devkit services:env typesense | sed -n 's/^TYPESENSE_API_KEY=//p') && curl -s -H "X-TYPESENSE-API-KEY: $KEY" http://127.0.0.1:8108/health && echo
brew install typesense/tap/typesense-server (first time) · starting typesense on 127.0.0.1:8108 · {"ok":true}
devkit services:list --json | python3 -c 'import json,sys; [print(i["name"], i["port"], i["options"].get("peering_port")) for i in json.load(sys.stdin) if i["type"]=="typesense"]'
typesense 8108 8107   ← the peering listener is per instance; a second typesense would get 8109/8110
Tapped formulae: the tap resolves typesense-server to typesense-server@30.2, a different formula name, so a fully-qualified install's item-level trust isn't enough under Homebrew 6. devkit runs brew trust typesense/tap before the install — you'll see it as the first line — and trusts only taps a driver declares.

3SeaweedFS as S3 ~5 min

devkit services:create seaweedfs && sleep 5 && curl -s -X PUT http://127.0.0.1:8333/devkit-test -o /dev/null -w '%{http_code}\n' && curl -s http://127.0.0.1:8333/ | grep -o '<Name>[^<]*</Name>'
brew install seaweedfs (first time) · starting seaweedfs on 127.0.0.1:8333 · 200 · <Name>devkit-test</Name>
devkit services:env seaweedfs
FILESYSTEM_DISK=s3 · AWS_ACCESS_KEY_ID=devkit · AWS_SECRET_ACCESS_KEY=devkit · AWS_DEFAULT_REGION=us-east-1 · AWS_BUCKET= · AWS_ENDPOINT=http://127.0.0.1:8333 · AWS_URL=… · AWS_USE_PATH_STYLE_ENDPOINT=true
Master 9333, volume 8080 (or the next free — Reverb also wants 8080), filer 8888, S3 8333: all under one agent, all bound to 127.0.0.1. No S3 auth config means any key works, which is why AWS_ACCESS_KEY_ID=devkit is a constant, not a secret. A site sets AWS_BUCKET itself; Phase 3's init will create the bucket.
A single PUT /bucket is the whole S3 smoke test. With the AWS CLI installed: aws --endpoint-url http://127.0.0.1:8333 s3 ls (any key configured) lists the same.

4Reverb, inside smoke ~5 min

cd ~/Sites/smoke && composer require laravel/reverb && cd -
devkit services:create reverb --site=smoke && curl -sI http://127.0.0.1:$(devkit services:env reverb-smoke | sed -n 's/^REVERB_PORT=//p')/ | head -1
starting reverb-smoke on 127.0.0.1:8080 (or the next free port if seaweedfs's volume listener took 8080) · HTTP/1.1 404 Not Found — Reverb answering; 404 is its response to a plain GET
devkit services:env reverb-smoke && devkit services:env reverb-smoke >> ~/Sites/smoke/.env && tail -12 ~/Sites/smoke/.env
BROADCAST_CONNECTION=reverb · REVERB_APP_ID/KEY/SECRET (generated once, kept in service.json) · REVERB_HOST/PORT/SCHEME · VITE_REVERB_*
The instance runs php artisan reverb:start with the site's PHP — the isolated one if the site is isolated — from the site's directory. That php path is captured at create; if you later isolate smoke to another version, services:delete reverb-smoke && services:create reverb --site=smoke picks up the new one (secrets change too — re-append the env).
"laravel/reverb is not installed in smoke" — 4.1 didn't run, or ran in another directory. It checks vendor/laravel/reverb in the site.
Reverb crash-loops with "The environment file is invalid! Failed to parse dotenv file" — the site's .env has a non-KEY=VALUE line, typically an error message captured by a redirect (running the append before the instance existed). grep -nvE '^\s*(#|$|[A-Za-z_][A-Za-z0-9_]*=)' ~/Sites/smoke/.env shows it; delete it and services:restart. services:env now writes errors to stderr so a redirect can't pick them up.
Reverb won't install: "laravel/reverb … require guzzlehttp/psr7 ^2.6 … fixed to 3.x" — the site's skeleton is on Guzzle 8 and no Reverb release supports psr7 3 yet. composer require laravel/reverb -W if the rest allows the downgrade; otherwise test on a Laravel 12 app (composer create-project laravel/laravel:^12 ~/Sites/reverb-test) until Reverb catches up.

!Troubleshooting

seaweedfs: "did not start answering on 8333" — the S3 gateway comes up after master, volume and filer; on a slow disk that exceeds nothing, but check services:logs seaweedfs for a port conflict on one of the aux listeners (services:list --json shows which it chose).
typesense: crash-loop with "peering port" — another process holds the aux port it chose at create; lsof -nP -iTCP:<port> -sTCP:LISTEN, then delete and recreate so a fresh port is allocated.
reverb: exits immediately, log says "reverb:start" is not defined — the site's PHP found the wrong vendor dir, i.e. WorkingDirectory isn't the site. plutil -p ~/Library/LaunchAgents/dev.zhuk.devkit.svc.reverb-<site>.plist | grep WorkingDirectory.
meilisearch: "data.ms is locked" — a previous instance is still holding the same db path; services:doctor shows the stale one.
