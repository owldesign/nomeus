!Troubleshooting

Dumps still print in the browser with capture on — php-fpm hasn't loaded the ini: valet restart php. Check from a request: a route with return ini_get('auto_prepend_file'); must show the prepend path. The CLI (php --ini) is not proof for fpm.
Dumps print in the terminal with capture on — the server isn't running (VarDumper falls back to printing when nothing listens): devkit services:list, services:logs dumps.
Debug page says "prepend ini missing for a PHP version" — a PHP was installed after dumps:install: run it again (and restart fpm).
Queries/Logs tabs stay at 0 for a site — it doesn't have zhuk/devkit-client (see 3a 2.1 or init), or its APP_ENV isn't local/development/testing, or DEVKIT_DUMPS=false in its .env.
Everything from one site groups as one request — Laravel Octane keeps the process alive between requests, so VarDumper's per-request identifier doesn't reset. Octane is out of scope for now; the client package's request id would need an Octane request-started hook.
Composer complains about the prepend — it doesn't; but any PHP tool that forbids auto_prepend_file (none common) can be run with php -d auto_prepend_file= ….
