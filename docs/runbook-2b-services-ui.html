!Troubleshooting

Task failed: "Domain does not support specified action" / exit 125 — see 1.1. Everything else in 2b is fine; this is the one thing php-fpm's session context can change, and it has a one-line fix once confirmed.
"copy .env" does nothing / says copy failed — the dashboard is on plain http, which browsers don't treat as a secure context, so the clipboard API is absent. devkit falls back to the legacy copy path; if even that fails, the block is select-all: click it, ⌘C. Permanent fix: devkit secure devkit — https://devkit.test is a secure context (the installer now does this when Valet is trusted).
Task failed with brew "Refusing to load formula … untrusted tap" — a new formula from a tap you haven't trusted. brew trust <tap> once (runbook 0a's Homebrew 6 note).
Create task stuck "running" for minutes — brew is downloading a bottle. Tasks page → log shows progress; create's timeout is 30 minutes.
Red LED, "exit 1" in the pid column, restart does nothing — a crash loop: launchd relaunches a process that dies at once. Expand the row: the log says why. Postgres clone with lock file "postmaster.pid" already exists was the first case (the copy carried the source's lock; clone now waits for it and strips it). Manual fix for any leftover: devkit services:stop X && rm ~/.devkit/services/X/data/postmaster.pid && devkit services:start X — start also removes stale locks itself now. The second case, data directory … has invalid permissions, was the copy landing as 0755; clone now mirrors the source's 0700. Manual fix: chmod 700 ~/.devkit/services/X/data && devkit services:restart X.
Row shows a red LED "formula missing" — the instance's formula was uninstalled behind devkit's back (brew uninstall). brew install <formula> brings it back with the data intact.
