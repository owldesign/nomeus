1The instance ~2 min

devkit mail --create && curl -s http://127.0.0.1:8025/api/v1/messages | head -c 120; echo
starting mailpit on 127.0.0.1:1025 · http://127.0.0.1:8025 · SMTP 127.0.0.1:1025 · Mailpit's UI opens · {"total":0,"unread":0,…}
devkit status | grep mailpit && devkit services:env mailpit
mailpit running · MAIL_MAILER=smtp MAIL_SCHEME=null MAIL_HOST=127.0.0.1 MAIL_PORT=1025 MAIL_USERNAME=null MAIL_PASSWORD=null MAIL_ENCRYPTION=null
Still a service instance like the others: services:list shows it, launchd keeps it up, the Services page can stop it. The status strip's mailpit LED reads its SMTP port.

2Wire smoke ~4 min

cd ~/Sites/smoke && composer config repositories.devkit path ~/Code/devkit/packages/devkit-client && composer require --dev zhuk/devkit-client:@dev && php artisan about | grep -i devkit; cd -
symlinked into vendor/zhuk/devkit-client · package discovery registers Zhuk\DevkitClient\DevkitClientServiceProvider
Path repositories symlink, so edits to packages/devkit-client are live in every site that requires it. --dev because it must never ship: the provider only registers in local/development/testing anyway.
cd ~/Sites/smoke && sed -i '' '/^MAIL_/d' .env && devkit services:env mailpit >> .env && printf 'MAIL_FROM_ADDRESS=hello@smoke.test\nDEVKIT_MAIL_TAG=smoke\n' >> .env && grep -E '^(MAIL_|DEVKIT_)' .env; cd -
the seven MAIL_ lines from mailpit, plus MAIL_FROM_ADDRESS and DEVKIT_MAIL_TAG=smoke
Laravel loads .env immutably: the first definition of a key wins, so appended duplicates are ignored. The skeleton's .env already has MAIL_* — hence the sed first. 3b's init does this replacement properly.

3Send, and see it filed ~3 min

cd ~/Sites/smoke && php artisan tinker --execute="Mail::raw('hello from smoke', fn(\$m) => \$m->to('you@example.test')->subject('devkit mail test'));" && cd - && curl -s http://127.0.0.1:8025/api/v1/tags
["smoke"]
open https://devkit.test/mail
apps rail: all · smoke → click smoke → "devkit mail test" from hello@smoke.test → click it → "hello from smoke" in the preview (text part; HTML messages render through Mailpit's view, with a show text/show html toggle) · "delete all" clears the smoke inbox only
Tags are the inbox. An app without the client package still lands in "all" — untagged. Two apps sending at once stay separate as long as each has the package (or sets X-Tags itself).

!Troubleshooting

Message arrives untagged (only under "all") — the package isn't registered: composer show zhuk/devkit-client and php artisan package:discover. Or APP_ENV isn't local/development/testing — the provider stays out otherwise, on purpose.
Nothing arrives at all — the site still has the skeleton's MAIL_* (log mailer, or port 2525). php artisan config:show mail.mailers.smtp must say host 127.0.0.1 port 1025. If you cached config, php artisan config:clear.
Mail page: "Mailpit is not answering on http://127.0.0.1:8025" — the instance is stopped or crashed: devkit services:list / services:logs mailpit. Port 8025 taken by an old brew services mailpit? brew services stop mailpit.
Preview pane is blank — the iframe loads Mailpit's /view/<id>.html from 127.0.0.1:8025; a browser extension blocking mixed content or third-party frames on an https dashboard can hide it. "open in Mailpit" always works.
