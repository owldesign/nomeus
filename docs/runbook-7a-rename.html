!Troubleshooting

"Class App\Support\DevkitConfig not found" / duplicate class — the 0.1 rm list wasn't run, or composer dump-autoload wasn't. Both are in 0.1's line.
An instance is "kept stopped" after the migration — its formula binary or data is fine (nothing moved but the directory); nomeus services:logs <name> says why, usually a port the old agent still held for a second. nomeus services:start <name>.
Dashboard: nomeus.test shows the Valet 404 — the link exists but nginx wasn't reloaded for the new host; valet restart nginx. https needs the certificate step, which the migration runs when devkit.test was secured — otherwise nomeus secure nomeus.
Debug page: nothing arrives from a site — its .env has the old keys (fine) but php-fpm still loads the old prepend path: valet restart php (the migration does it; a failed restart is printed).
