2The Logs page ~5 min

open https://devkit.test/logs
rail: each site with logs → its files (newest first, sizes) · "valet" group with nginx-error.log / fpm-php.www.log if present · the most recently written file is selected

the ERROR entry → "+N" expands the context and trace → every /path/file.php:line and /path/file.php(line) is a link → click one → your IDE (config.json "ide", PhpStorm by default) opens the file at that line
Links use the IDE's URL scheme (phpstorm://, vscode://, cursor://, zed://, subl://). The first click makes the browser ask permission to open the app — allow and remember. devkit config:set ide vscode switches for everything: links here, devkit edit, the Sites page.

Scroll up while following and the view stays where you are; scroll back near the bottom and it resumes auto-scrolling. Big files show only their last 64 KB ("showing the tail" in the header) — older entries are still in the file, just not loaded.

!Troubleshooting

Rail is empty — no site has a storage/logs/*.log yet; Laravel creates it on the first write. devkit logs smoke says the same and lists the sites that do have one.
Clicking a file:line does nothing — the IDE has no URL scheme handler registered (Sublime needs the "URL scheme" package; PhpStorm/VS Code/Cursor/Zed register theirs on first launch). devkit edit <path> uses the same scheme from the terminal and shows the error if there is one.
An entry shows as one giant line without a trace — that app's logger is configured without inline line breaks (a custom formatter); the message is intact, the trace just isn't split. The parser keys on Laravel's default LineFormatter.
Entries appear twice / out of order after a clear — a rotation (daily log switching files) is a new source, not a truncation; pick the new file in the rail. Truncation of the same file is detected (offset > size) and the view restarts.
