DB_CONNECTION=mysql · DB_DATABASE=<its schema>   ← put exactly that schema in database:, so init reuses it
cat > ~/Sites/coavaorders.com/dev.yml <<'EOF'

site skip · tls skip/run · mysql → mysql skip (running on 3306) · db:mysql run (CREATE DATABASE IF NOT EXISTS — a no-op for the existing schema) · redis skip · mail skip · client run · env run
devkit init ~/Sites/coavaorders.com
client package required · .env: MAIL_* now point at mailpit, DB_* unchanged in value, DEVKIT_MAIL_TAG=coavaorders
init never drops or renames anything: databases are created only if missing, .env keys are replaced in place. What it does change on an existing site is MAIL_* (to Mailpit) and APP_URL/APP_NAME — glance at git diff .env if the site tracks one, or at the "set N" list init prints.
The site's .env says DB_PORT=3306 but the manifest resolved a different instance? instance: pins it. Two DB types in one manifest (postgres and mysql) both want DB_* — first listed wins; use env: for the other's keys.

!Troubleshooting

Class "Symfony\Component\Yaml\Yaml" not found — 0.1's composer require symfony/yaml didn't run.
[php] … php@X is not installed — the manifest asks for a version devkit doesn't have: devkit php:install X, or change php:.
[db:…] createdb … failed: role "postgres" does not exist — an adopted cluster whose postAdopt didn't get to create the role. psql -U <your user> -d postgres -c "CREATE ROLE postgres SUPERUSER LOGIN" on that instance's port.
[client] composer require … exited 1 — the site's dependency set can't take the package (it only needs illuminate/support ^11–13); the composer output above the line says which constraint. client: false in the manifest skips it.
init from the dashboard hangs — a post-init script is waiting for input. Scripts run with --no-interaction semantics only if they honour it; add the flag to the command in dev.yml (e.g. migrate --force).
